# 平台作为统一模型入口 — 对接指南

> 场景：应用/开发者不带模型厂商 Key，只带**平台分配的 Key** 访问平台地址，
> 由平台统一网关转发到**本地部署的模型**（模型本身无需 Key）。
>
> 这是"大模型监测管理平台"的核心用途：**对应用是模型厂商，对模型是统一调用方**。

---

## 1. 使用流程（给应用开发者的视角）

```
1. 管理员在平台「Key 管理」新建 Key → 生成 sk-xxx（只展示一次）
2. 管理员在「模型管理」登记本地模型：
     名称 = 应用调用时用的 model 名（如 local-qwen）
     地址 = 本地模型服务地址（如 http://10.51.13.7:8001/v1，vLLM/OneAPI 等）
     API Key = 留空（本地模型无 Key）
3. 应用用上面的 Key 调平台的 OpenAI 兼容地址：
     POST http://<平台地址>/v1/chat/completions
     Authorization: Bearer sk-xxx
     body: {"model": "local-qwen", "messages": [...]}
4. 平台校验 Key → 解析模型 → 校验权限 → 转发本地模型 → 返回 OpenAI 格式
```

## 2. 平台自带入口（无需 Higress 即可用）

平台后端已内置 OpenAI 兼容代理（`ProxyService` + `/v1/chat/completions`），
**只要 api-server 跑着就能用**，便于先验证链路：

```bash
# 示例：直接打到 api-server
curl http://10.51.13.7:8000/v1/chat/completions \
  -H "Authorization: Bearer sk-你平台发的key" \
  -H "Content-Type: application/json" \
  -d '{"model":"local-qwen","messages":[{"role":"user","content":"你好"}]}'
```

若 api-server 未对外暴露 8000，经前端 nginx 也行——把下面 location 加入
`frontend/nginx.conf` 后重建 web（推荐正式对外用 Higress，见第 4 节）。

```nginx
location /v1/ {
    proxy_pass http://api-server:8000;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

## 3. 网关 Key 校验端点（供 Higress 等外部网关回调）

| 项 | 值 |
|----|-----|
| 方法/路径 | `POST /api/v1/gateway/verify-key` |
| 请求体 | `{"key": "sk-xxx"}` |
| 成功 | `{"code":0,"data":{"key_id":1,"allowed_model_ids":null,...}}`（`allowed_model_ids=null` 表示不限模型） |
| 失败 | `{"code":401,"message":"invalid key"}` |

Higress 配置自定义鉴权时，可把该端点作为 ext-auth 回调：网关收到请求 →
调 verify-key → 放行/拒绝 → 转发本地模型。

## 4. 完整链路（Higress 接入后）

```
应用 ──带平台Key──► Higress:8080
                      │  ① 校验 Key（回调平台 verify-key / 或本地缓存）
                      │  ② AI 路由 → Provider
                      ▼
              本地模型（vLLM/OneAPI/...，无 Key）
```

详见 `deploy/higress-setup.md`（第 4 步 Provider/路由，第 5 步 Key 鉴权）。

---

## 5. 校验行为说明（Key ↔ 模型权限）

| 情况 | 结果 |
|------|------|
| Key 不存在 / 非 active / 已过期 | 401 |
| 请求缺 Authorization | 401 |
| 模型不存在或状态非 online | 404 |
| Key 未绑定任何模型 | 默认可访问**全部**模型 |
| Key 绑定了模型，但请求的不在内 | 403 |
| Key 绑定了模型，且命中 | 放行转发 |

## 6. 日志与统计

每次转发都会写一条 `api_request_log`（含 prompt/completion tokens、耗时、状态码、
Key、模型），供「Token 统计」模块聚合。转发错误（超时 504 / 上游 502）同样记录。
