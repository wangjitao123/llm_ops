# M01 — 模型管理模块

## 模块概述

模型管理模块是大模型监测管理平台的核心模块之一，负责统一管理企业内所有大模型的接入、配置、状态监控和版本管理。通过该模块，平台管理员可以一站式接入 DeepSeek、GPT、通义千问、文心一言、Claude、Gemini 等多种大模型，实时监控模型运行状态，并管理模型版本的生命周期。

模型管理模块为下游模块（统一网关、Token 统计、模型对比等）提供基础数据支撑，是平台正常运行的前提条件。

### 核心能力

- **统一接入**：支持多种模型厂商的标准化接入，预设常见模型模板
- **实时监控**：30 秒心跳检测，自动判定模型在线/高延迟/离线状态
- **版本管理**：支持模型版本记录、切换与回滚，最多保留 10 个历史版本
- **配置管理**：统一管理 API 地址、Key、QPS 上限、超时时间、负载权重等参数

## 功能点清单

### F-002 模型接入与配置（Must | RICE 评分 9.5）

**功能描述**：支持接入多种大模型并提供统一配置界面。

| 功能点编号 | 功能点名称 | 描述 | 优先级 | 复杂度 |
|-----------|-----------|------|--------|--------|
| F-002 | 模型接入与配置 | 添加/编辑/删除模型配置，支持多种模型厂商 | Must | M |
| F-002.1 | 模型列表 | 展示所有已接入模型，支持搜索和筛选 | Must | S |
| F-002.2 | 模型配置表单 | 配置 API 地址、Key、QPS、超时、权重等参数 | Must | M |
| F-002.3 | 模型连通性测试 | 保存配置时自动检测 API 可达性 | Should | M |
| F-002.4 | 模型启停控制 | 启用/停用模型 | Must | S |

**业务规则**：
- 支持配置：模型名称、API 地址、API Key、QPS 上限、超时时间、模型权重
- 模型权重用于网关负载均衡时的加权轮询
- 支持模型启停控制
- 预设常见模型模板（DeepSeek、GPT、通义千问、文心一言、Claude、Gemini）

**异常处理**：
| 异常场景 | 处理方式 | 用户提示 |
|----------|----------|----------|
| 配置的 API 地址不可达 | 保存时进行连通性测试 | "模型 API 不可达，请检查地址" |
| QPS 配置超过默认上限 | 保存时提示 | "建议 QPS 不超过 500" |

---

### F-003 模型状态监控（Must | RICE 评分 8.5）

**功能描述**：实时监控各模型运行状态，包括在线/离线、响应时间、QPS、错误率等指标。

| 功能点编号 | 功能点名称 | 描述 | 优先级 | 复杂度 |
|-----------|-----------|------|--------|--------|
| F-003 | 模型状态监控 | 实时监控模型运行状态、响应时间、QPS | Must | M |

**业务规则**：
- 健康检查：每 30 秒向模型 API 发送心跳请求，连续 3 次失败判定为离线
- 延迟阈值：< 500ms 正常，500ms–2s 高延迟，> 2s 严重延迟
- 状态类型：在线（正常响应）、高延迟（响应时间超过阈值）、离线（心跳失败）、待配置（未完成初始化）
- 模型离线时自动触发告警通知（钉钉推送）
- 离线模型恢复后自动更新状态，通知管理员

---

### F-004 模型版本管理（Should | RICE 评分 6.0）

**功能描述**：管理模型的不同版本，支持版本切换和回滚。

| 功能点编号 | 功能点名称 | 描述 | 优先级 | 复杂度 |
|-----------|-----------|------|--------|--------|
| F-004 | 模型版本管理 | 管理模型版本，支持版本切换和回滚 | Should | M |

**业务规则**：
- 版本信息：版本号、发布时间、状态（当前/历史）、变更说明
- 当前正在使用的版本标记为"当前"
- 支持回滚到任意历史版本，回滚后原版本标记为"历史"
- 新版本接入时自动保留上一个版本
- 最多保留 10 个历史版本
