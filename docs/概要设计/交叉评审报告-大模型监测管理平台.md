## 3. 遗漏问题（🟡）

### 问题 1: 缺少 SSO 配置存储表

| 来源 | PRD F-018：SSO 统一认证（Must） |
|------|--------------------------------|
| 问题 | PRD 明确 SSO 为 Must 优先级（系统前置条件），但数据库设计中未包含 SSO 配置存储表 |
| 建议 | 新增 `system_config` 表或 `sso_config` 表，存储 SSO 协议类型、认证地址、Client ID/Secret 等配置 |
| 严重程度 | 🟡 高（Must 功能缺少数据存储） |

### 问题 2: Token 统计缺少"按用户"维度

| 来源 | PRD F-008.3：按用户统计 Token 消耗（Should） |
|------|----------------------------------------------|
| 问题 | 功能点清单中 F-008.3 明确要求"按用户维度查看 Token 消耗"，但 `token_stats_hourly` 和 `token_stats_daily` 表的 `dimension_type` 枚举只定义了 `model/application/key`，缺少 `user` 维度 |
| 建议 | 在 `dimension_type` 枚举中增加 `user` 维度，或在 `api_request_log` 表中增加 `created_by` 字段关联用户 |
| 严重程度 | 🟡 中（Should 功能部分遗漏） |

### 问题 3: 缺少费用报表导出配置表

| 来源 | PRD F-009：多维度费用报表（Must） |
|------|----------------------------------|
| 问题 | F-009 要求"支持导出 CSV/Excel"，但数据库设计中未预留导出任务记录、导出文件路径等字段 |
| 建议 | 新增 `export_task` 表记录异步导出任务（任务ID、类型、参数、状态、文件路径、过期时间），或作为应用层逻辑处理 |
| 严重程度 | 🟡 低（可纯应用层实现，不强制要求数据库表） |

## 4. 待确认问题（⚪）

### 问题 4: 数据集版本管理粒度

| 来源 | PRD F-015.4：数据集版本管理（Could） |
|------|--------------------------------------|
| 问题 | 功能点清单中 F-015.4 要求"数据集的版本控制和回退"，但数据库设计仅在 `dataset` 表中有 `version` 字段，无独立版本表 |
| 建议 | 如果需要独立版本管理（每次修改生成新版本），建议新增 `dataset_version` 表；如果只是简单版本号管理，当前设计可满足 |
| 待确认 | 请问数据集版本管理需要独立版本历史表，还是仅用版本号字段即可？ |

### 问题 5: 微调超参数配置模型

| 来源 | PRD F-014.2：创建微调任务 |
|------|--------------------------|
| 问题 | 微调任务的 `hyper_params` 字段为 JSONB 类型，但未定义具体的超参数结构 |
| 建议 | 建议明确定义超参数 JSON 结构，例如：`{"learning_rate": 0.0001, "epochs": 3, "batch_size": 8, "warmup_steps": 100, "lr_scheduler": "cosine", "optimizer": "adamw", "max_seq_length": 2048, "lora_rank": 8, "lora_alpha": 16, "lora_dropout": 0.05}` |
| 待确认 | 请问微调支持的超参数范围是否按上述标准 LoRA 参数配置？ |

### 问题 6: 模型路由策略的权重配置

| 来源 | PRD F-011.2：路由策略 |
|------|----------------------|
| 问题 | `route_rule_model` 表中有 `weight` 和 `priority` 字段，但 Higress 的配置方式与传统数据库配置不同 |
| 建议 | 需要在架构设计中补充 Higress 与后端数据库的配置同步机制：后端的路由规则变更 → 推送到 Higress 配置 → 热加载生效 |
| 待确认 | 请问路由规则配置是通过 API 实时同步到 Higress，还是通过配置文件热加载？ |

### 问题 7: 模型对比评估结果存储

| 来源 | PRD F-017：模型对比评估 |
|------|------------------------|
| 问题 | `model_eval` 表中 `result` 字段为 JSONB 类型，未定义内部结构 |
| 建议 | 建议明确定义评估结果 JSON 结构，例如：`{"dimensions": {"quality": 85, "latency": 70, "cost": 90, "context": 80, "stability": 75, "throughput": 85, "ease_of_use": 80}, "overall_score": 80.7, "models": [{"id": 1, "name": "deepseek-v3", "scores": {...}}, {"id": 2, "name": "gpt-4o", "scores": {...}}]}` |
| 待确认 | 请问模型对比的评分维度和权重是否按默认值（质量30%、延迟15%、成本15%、上下文10%、稳定性10%、吞吐量10%、易用性10%）配置？ |
