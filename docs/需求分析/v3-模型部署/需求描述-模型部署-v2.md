# 需求描述 - 模型部署功能 v2

## 项目名称
大模型监测管理平台（AI网关）

## 需求描述
在现有平台基础上增加**模型部署**功能，支持对**已有模型端点**（不论运行方式）进行注册、配置、监控和路由管理，同时也支持从量化结果一键部署新容器化推理服务。

## 核心价值
1. **统一注册**：无论模型跑在 conda 环境还是 Docker 容器里，统一在平台注册和管理
2. **配置标准化**：每个模型可以绑定 system prompt、工具定义（tool call）、web search 参数等
3. **健康监控**：对所有注册的端点进行心跳检测和指标采集
4. **网关集成**：注册后自动同步到统一网关，下游应用无感切换

## 部署方式（两种模式）

### 模式A：注册已有端点
适用于已经在 conda 环境或 Docker 里跑起来的模型。
- 用户提供：端点 URL、部署名称、运行方式（conda/docker/其他）
- 平台提供：健康检查、延迟/QPS 采集、配置管理
- 不提供：生命周期管理（启停由用户手动维护）

### 模式B：平台一键部署
适用于：
- 模型量化模块产出的量化模型 → 自动拉起 vLLM Docker 容器
- HuggingFace 模型 → 选择引擎（vLLM/TGI/SGLang）自动部署
- 平台提供：完整生命周期管理（部署/启动/停止/重启/销毁）

## 配置管理（关键需求）
每个已注册的部署需要支持以下配置项：

| 配置类别 | 配置项 | 说明 |
|---------|--------|------|
| 基本参数 | temperature, top_p, max_tokens, frequency_penalty | 推理采样参数 |
| 系统提示词 | system_prompt | 可选的 system prompt 模板，不同部署可不同 |
| 工具调用 | tools (function calling 定义列表) | JSON Schema 格式的工具定义，用于 tool call 场景 |
| 知识搜索 | web_search 配置 | 搜索引擎 API、是否启用 RAG、检索参数 |
| 速率控制 | 并发数、QPS 上限 | 网关限流使用 |
| 环境变量 | 自定义 env vars | 用于 conda/Docker 场景传递特有配置 |

## 用户场景

### 场景A：注册一个 conda 里跑着的 vLLM 服务
1. 运维在 conda 环境启动 vLLM：`python -m vllm.entrypoints.openai.api_server --model Qwen2.5-7B --port 31000`
2. 在平台点「注册已有端点」，填写名称、URL `http://10.51.13.7:31000`、运行方式「conda」
3. 配置 tool call 定义（让模型知道有哪些工具可用）
4. 配置 system prompt 模板
5. 平台开始健康检查，自动注册到网关

### 场景B：从量化结果部署一个容器
1. 量化模块产出模型到 `/models/qwen2.5-7b-gptq/`
2. 点「新建部署」→ 选择模型来源「量化完成」→ 选择该模型
3. 选择引擎 vLLM，GPU 分配 1 卡，点部署
4. 平台自动拉起 vLLM Docker 容器，完成后自动注册

## 技术约束
- GPU 8×L20 (48GB)
- conda 环境由运维维护，平台不管理 conda 生命周期
- Docker 容器由平台管理（启动/停止/销毁）
- 推理引擎支持：vLLM（首选）、TGI、SGLang
- 健康检查：HTTP GET `/health`，30 秒间隔，3 次失败标记异常
- 工具调用格式：兼容 OpenAI function calling 格式
- web search：预留接口，由具体部署自行对接搜索引擎
