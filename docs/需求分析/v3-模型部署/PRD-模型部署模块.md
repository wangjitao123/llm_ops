## 1. 需求概述

### 1.1 需求背景
当前平台已完成模型量化、模型对比、模型微调等功能，但量化后的模型仅能保存到共享卷，无法直接对外提供推理服务。同时，团队有大量模型以 conda 环境进程或 Docker 容器方式运行，缺乏统一的管理视图和配置中心。

主要痛点：
- **量化模型无"最后一公里"**：量化完成后无法一键部署为推理服务
- **已有端点分散管理**：conda 环境/Docker 中跑着的模型没有统一的健康监控和配置管理
- **配置散落**：每个模型都有 tool call 定义、system prompt、搜索配置等，散落在各自的启动脚本中
- **网关集成手动**：新增模型后需手动在模型管理填 URL 和 Key

### 1.2 需求目标
| 目标类型 | 目标描述 | 衡量指标 |
|----------|----------|----------|
| 业务目标 | 实现量化→部署→使用的完整闭环 | 量化模型一键部署成功率 ≥ 95% |
| 业务目标 | 统一管理所有模型端点（不限运行方式） | 覆盖 100% 的在线模型 |
| 用户目标 | 3 分钟内完成一个新模型注册 | 注册流程 ≤ 10 步 |
| 用户目标 | 5 分钟内从量化结果完成部署 | 部署准备时间 ≤ 5 分钟 |
| 技术目标 | 端到端延迟 ≤ 5ms（不含推理） | 网关转发开销 |

### 1.3 预期收益
- **直接收益**: 消除量化→部署的断点，减少手工部署操作
- **间接收益**: 统一的管理和监控视图降低运维成本
- **管理收益**: tool call / web search / system prompt 集中配置，无需散落在启动脚本

### 3.2 功能详情

#### DPL-001: 部署列表与概览
**功能描述**: 展示所有已注册/已部署的模型端点列表，支持按状态、运行方式筛选。

**业务规则**:
- 每行展示：部署名称、基座模型、运行方式（conda/Docker/平台管理）、状态（运行中/已停止/部署中/异常）、端点URL、配置摘要标签（tools/search/sys_prompt）、健康率
- 运行方式分为三类，操作按钮按类型差异化：
  - 平台管理：完整启停/重启/配置/监控
  - conda：仅配置/监控（启停按钮 disabled，提示"用户手动管理"）
  - Docker：仅配置/监控（启停按钮 disabled）
- 顶部统计卡片：总部署数、运行中数、GPU 占用、异常数
- 支持按状态、运行方式、关键词搜索筛选

**原型引用**: prototype-v2/index.html — 部署列表页

#### DPL-002: 注册已有端点
**功能描述**: 将已经在 conda 环境或 Docker 容器中运行的模型端点注册到平台。

**业务规则**:
- 必填：部署名称、端点 URL（OpenAI 兼容格式）、运行方式
- 选填：基座模型、备注
- 注册后立即开始健康检查（GET /health 或 /v1/models，30 秒间隔）
- 注册时自动检测端点可达性
- 注册完成后可继续编辑配置（tool call、system prompt、web search、采样参数、环境变量）
- 注册后自动出现在模型管理可选列表中

**原型引用**: prototype-v2/index.html — "注册已有端点"弹窗

#### DPL-003: 新建平台部署
**功能描述**: 从量化模型或 HuggingFace 模型一键部署为推理服务。

**业务规则**:
- 模型来源两种：
  - 量化完成：从模型量化模块读取已完成量化的模型列表，选择后自动填充路径
  - HuggingFace：输入模型 ID，平台自动下载
- 推理引擎选择：vLLM（首选）、TGI、SGLang
- GPU 分配：支持 1/2/4 卡 TP，自动选择或手动指定 GPU 编号
- 部署名称为必填，自动生成默认名称
- 部署流程：创建 Docker 容器 → 等待就绪 → 健康检查通过 → 自动注册
- 部署中状态下显示进度条和日志

**原型引用**: prototype-v2/index.html — "新建部署"弹窗

#### DPL-004: Tool Call 配置管理
**功能描述**: 为每个部署配置 OpenAI 兼容的 function calling 工具定义。

**业务规则**:
- 每个部署可绑定 0-N 个工具定义
- 工具定义格式：JSON Schema（OpenAI function calling 标准）
- 支持添加、编辑、删除、排序工具
- 配置保存后网关自动注入到请求中
- 支持导入/导出工具定义为 JSON

**业务规则**:
- 一次部署配置的工具只对该部署生效
- 不同部署可绑定相同工具，各自维护

#### DPL-005: System Prompt & 采样参数配置
**功能描述**: 为部署配置 system prompt 模板和推理采样参数。

**业务规则**:
- system prompt 模板：可选，配置后网关在每个请求前自动注入
- 采样参数：temperature（默认 0.7）、max_tokens（默认 4096）、top_p（默认 0.9）、frequency_penalty（默认 0.0）
- 采样参数为默认值透传，用户请求可覆盖

#### DPL-006: Web Search 配置
**功能描述**: 为部署配置联网搜索能力。

**业务规则**:
- 搜索引擎 API：支持自定义搜索服务、Bing Search API、SerpAPI、本地 Elasticsearch
- 配置：API Endpoint、API Key（可选）、最大返回条数
- RAG 模式：搜索后直接返回 / 搜索后模型总结 / 启用 RAG 检索
- 启用后网关在请求中注入搜索上下文

#### DPL-007: 部署启停控制
**功能描述**: 对平台管理的部署进行启动、停止、重启操作。

**业务规则**:
- 仅对「平台管理」类型的部署可用
- conda/Docker 类型的部署按钮灰化，提示用户手动管理
- 停止：停止 Docker 容器，标记状态为"已停止"，从网关自动移除
- 启动：重启容器，恢复健康检查后自动注册
- 重启：先停止再启动

#### DPL-008: 健康检查与监控
**功能描述**: 对所有已注册/已部署的端点进行持续健康检测。

**业务规则**:
- 检测方式：HTTP GET `/health` 或 `/v1/models`（视引擎类型自动选择）
- 检测间隔：30 秒
- 连续 3 次失败 → 标记为"异常"，触发告警
- 检测通过后自动恢复为"运行中"
- 记录健康率：最近 1 小时/24 小时/7 天
- 展示关键指标：QPS、P50/P99 延迟、当前请求数

#### DPL-009: 部署详情与日志
**功能描述**: 查看部署的详细信息、运行日志和监控指标。

**业务规则**:
- 概览页签：端点 URL、基座模型、引擎版本、GPU 分配、注册状态、QPS、延迟、健康率
- 配置页签：当前所有配置（tools/prompt/search/sampling/env）
- 日志页签：终端风格的运行日志，支持自动刷新
- 监控页签：QPS 趋势、延迟分布、错误率

#### DPL-010: GPU 资源拓扑视图
**功能描述**: 展示 8 张 L20 GPU 的资源使用情况。

**业务规则**:
- 每张 GPU 展示：显存使用量、当前运行的部署名称
- 空闲 GPU 推荐建议
- 新建部署时自动推荐最优 GPU

#### DPL-011: 自动注册到模型管理
**功能描述**: 部署成功后自动在模型管理模块创建对应记录。

**业务规则**:
- 注册内容：部署名称、端点 URL（自动填写）、生成 API Key（可选）、备注
- 注册后用户可直接在模型管理中选择该模型，通过网关调用
- 部署删除时同步移除模型管理记录
- 自动注册为可选开关，默认开启

#### DPL-012: 部署配置编辑
**功能描述**: 已注册/已部署的配置允许修改。

**业务规则**:
- 可编辑：tool call 列表、system prompt、采样参数、web search、环境变量
- 不可编辑：端点 URL、运行方式、基座模型
- 配置修改即时生效，网关后续请求使用新配置

#### DPL-013: 环境变量与自定义配置
**功能描述**: 支持为部署配置自定义环境变量。

**业务规则**:
- 键值对形式，用于传递特有配置到网关
- 仅存储和透传，平台不解析

#### DPL-014: 部署模板/快捷方式
**功能描述**: 提供常用部署配置模板。

**业务规则**:
- 预设模板：7B GPTQ 单卡、7B AWQ 单卡、14B AWQ 双卡 TP、32B GPTQ 4卡 TP
- 模板预设引擎、GPU 数、最大并发等参数
- 从量化结果部署时自动匹配推荐模板

## 4. 非功能需求

### 4.1 性能需求
| 指标 | 要求 |
|------|------|
| 健康检查间隔 | 30 秒 |
| 部署到就绪时间 | ≤ 5 分钟（7B 模型） |
| 配置生效延迟 | ≤ 30 秒（修改配置后） |
| 页面加载 | ≤ 2s |

### 4.2 安全需求
| 安全项 | 要求 |
|--------|------|
| 端点认证 | 部署自动生成随机 API Key |
| 配置加密 | API Key 和搜索 Key 加密存储 |
| 网络隔离 | 平台部署的容器仅对内网服务 |

### 4.3 可用性需求
| 指标 | 要求 |
|------|------|
| 系统可用性 | ≥ 99.9% |
| 健康检查精度 | ≤ 5% 误报率 |
| 数据持久性 | 部署配置持久化存储 |
