# 用户故事 - 模型量化模块

## US-QUANT-01：查看量化任务列表

**角色**：平台管理员  
**标题**：查看所有量化任务的状态和进度  
**故事**：作为平台管理员，我希望打开「模型量化」页面就能看到所有量化任务的列表，包括名称、量化方案、状态、进度，这样我可以快速了解当前的量化任务情况。  
**验收标准**：
1. 页面默认展示全部量化任务，按创建时间倒序排列
2. 每行显示任务名称、基座模型（HF ID）、量化方案标签（如 GPTQ W4A16）、状态指示器（圆点+文字）、进度条
3. 支持按状态筛选（全部/待提交/排队中/运行中/已完成/失败）

## US-QUANT-02：创建量化任务

**角色**：平台管理员  
**标题**：配置并创建新的量化任务  
**故事**：作为平台管理员，我希望在创建弹窗中填写 HuggingFace 模型 ID、选择量化算法和精度、配置校准数据，然后提交到 GPU Worker 自动执行，这样我不需要手动操作命令行或编写脚本。  
**验收标准**：
1. 点击「创建量化任务」打开弹窗
2. 可选的快速模板（W4A16-GPTQ 等）一键填充参数
3. 必填项：任务名称、HF 模型 ID
4. 可选项：输出模型名称
5. 量化配置：算法、权重精度、分组大小
6. 校准数据：默认 wikitext / 自定义文本 / 上传 .txt 文件
7. 高级设置（可折叠）：输出路径
8. 创建后自动提交，状态变为「排队中」

## US-QUANT-03：查看任务详情和日志

**角色**：平台管理员  
**标题**：查看量化任务的详细参数和运行日志  
**故事**：作为平台管理员，我希望点开任务详情能看到完整的参数配置、输出路径、结果模型链接，并实时查看 GPU Worker 的运行日志，这样可以排查问题或确认量化结果。  
**验收标准**：
1. 点击「详情」打开详情弹窗
2. 展示所有任务参数（名称、模型、算法、精度、分组、校准数据、路径等）
3. 结果模型显示为可点击的链接，跳转到模型管理
4. 日志面板按状态显示不同内容：运行中=实时日志，完成=完整流程，失败=错误堆栈
5. 错误信息高亮红色显示

## US-QUANT-04：管理任务生命周期

**角色**：平台管理员  
**标题**：提交、取消、重试、删除量化任务  
**故事**：作为平台管理员，我希望在「操作」列对任务进行生命周期管理：提交待处理的任务、取消运行中的任务、重试失败的任务、删除已完成的任务。  
**验收标准**：
1. pending→「提交执行」→变为 queued
2. queued/running→「取消」→变为 cancelled
3. failed→「重试」→变为 queued（清空错误信息）
4. completed/failed/cancelled→「删除」→从列表移除

## US-QUANT-05（系统角色）：GPU Worker 自动执行量化

**角色**：GPU Worker（系统）  
**标题**：自动从队列接收量化任务并执行  
**故事**：作为 GPU Worker，我希望自动从 RabbitMQ `quantization` 队列接收任务，下载 HuggingFace 模型、执行量化、保存结果、注册模型到平台，全程无人值守。  
**验收标准**：
1. 监听 `quantization` 队列，concurrency=1（串行防 OOM）
2. 下载模型前先更新状态为 running
3. 量化过程中更新进度（每处理完一个 transformer block 更新一次）
4. 量化完成后：保存模型到共享卷 + 创建 Model 记录 + 更新 task 状态
5. 失败时：捕获异常 + 记录错误信息 + 标记 failed
6. 支持 GPTQ / AWQ / bitsandbytes 三种算法实现

## US-QUANT-06：量化结果自动注册

**角色**：平台管理员  
**标题**：量化完成后的模型自动出现在模型管理中  
**故事**：作为平台管理员，我希望量化任务完成后，模型自动注册到「模型管理」中，这样我不用手动添加模型。  
**验收标准**：
1. 量化完成后自动创建 Model 记录
2. provider = "quantized"
3. version 格式：`1.0-q{wBits}a{aBits}-{algorithm}`
4. model_config 中记录量化参数（base_model / algorithm / weight_bits / group_size）
5. 描述中注明量化来源
