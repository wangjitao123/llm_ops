# 需求描述 - 模型压测功能 v2（决策已锁定）

## 项目名称
大模型监测管理平台（AI网关）

## 需求描述
在平台「进阶能力」下新增**模型压测**菜单，基于开源项目 [EvalScope](https://github.com/modelscope/evalscope)（Apache-2.0）的 `perf` 能力，提供 Web 化的大模型推理性能压测：

选择平台已注册/已部署的模型 → 配置压测参数 → 后台异步执行 → 实时查看进度 → 结束后查看 TTFT/TPOT/吞吐/成功率等指标 → **支持历史任务横向对比**。

## 已锁定决策（v2 新增）

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | **集成方式** | **方案 A：独立 `perf-worker` 容器**。`pip install evalscope`，Celery 队列 `perf`，调用 `run_perf_benchmark()`。不污染 api-server 镜像；压测不需要 GPU，普通机器可跑 |
| 2 | **默认数据集** | **`random`**（按 token 长度随机生成）。压测关注可控的输入/输出长度，不用问答数据集，保证指标可横向对比 |
| 3 | **历史对比** | **必做（Must）**。支持选择 2-N 个历史压测任务并排对比 TTFT / TPOT / 吞吐 / 成功率，用于量化前后、部署前后、参数调优前后对比 |
| 4 | **压测流量与 Token 统计** | **压测流量排除出 Token 用量统计**，避免污染费用报表 |

## 决策 4 的落地方式（关键技术点）

压测有两种打法，污染风险不同：

| 打法 | 是否经过平台网关 | 是否污染统计 | 用途 |
|------|-----------------|-------------|------|
| **直连模型** | ❌ 直打 `model.api_base_url` | 天然不污染 | 测**模型/引擎本身**性能（推荐默认） |
| **经网关** | ✅ 打平台 `/v1/chat/completions` | 会污染 | 测**端到端**性能（含网关开销） |

平台策略：
- 默认**直连模型**，天然不进 Token 统计
- 若用户显式选择「经网关压测」，perf-worker 注入请求头 `X-Perf-Test: 1`，网关识别后**跳过请求日志写入**（不计 Token、不计请求数、不计费用）

## 核心价值
1. **不用再上命令行**：EvalScope 是 CLI 工具，参数繁多；平台化后点选即可
2. **压测对象已在平台内**：模型已注册，URL/Key 自动带出，不重复填写
3. **结果可留存可对比**：历史任务入库，支持并排对比
4. **闭环验证**：量化/部署后一键压测，量化收益与部署性能有据可依

## 功能边界（基于 evalscope perf 实测能力）

### 压测模式
| 模式 | evalscope 参数 | 说明 |
|------|---------------|------|
| 闭环并发 | `parallel` + `number` | 固定并发打满，请求数固定 |
| 开环限速 | `open_loop=true` + `rate` | 按目标 RPS 发请求 |
| SLA 自动调压 | `sla_auto_tune=true` | 逐级加压，找满足 SLA 的最大并发拐点 |
| 多轮对话 | `multi_turn=true` | 带上下文的多轮压测 |

### 数据集类型
`random`（**默认**）、`openqa`、`speed_benchmark`、`share_gpt`、`line_by_line`、`longalpaca`、`custom`（用户上传 jsonl）

### 指标产出
- **TTFT**：均值 + P50/P90/P95/P99/Max
- **TPOT**（每 token 输出时间）
- **吞吐**：`output_throughput` (tok/s)、`request_throughput` (req/s)
- **成功率**：成功数 / 总数，错误按状态码分类
- 端到端延迟分位分布

## 技术约束
- **License**：Apache-2.0，需保留 EvalScope 版权声明与 NOTICE（前端/文档注明）
- **Python**：evalscope 要求 `>=3.11`，平台后端 3.12 ✅
- **依赖隔离**：evalscope 连带 `modelscope[datasets]`、`pandas`、`nltk` 等框架依赖（数百 MB），**必须独立容器**
- **执行位置**：纯 HTTP 负载生成，**不需要 GPU**
- **执行时长**：数十秒至数十分钟，必须异步 + 可中止
- **并发上限**：受 perf-worker 进程数与网络限制，平台侧需设上限（默认 500）

## 与现有模块的关系
| 现有模块 | 关系 |
|----------|------|
| 模型管理 | 压测目标从模型列表选，复用 `api_base_url` / `api_key` |
| 模型部署 | 部署完成后一键压测验证性能 |
| 模型量化 | 量化前后压测对比，量化收益量化评估 |
| Token 统计 | 压测流量通过 `X-Perf-Test` 头排除 |
