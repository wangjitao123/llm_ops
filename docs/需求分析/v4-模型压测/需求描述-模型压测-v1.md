# 需求描述 - 模型压测功能 v1

## 项目名称
大模型监测管理平台（AI网关）

## 需求描述
在平台「进阶能力」下新增**模型压测**菜单，基于开源项目 [EvalScope](https://github.com/modelscope/evalscope)（Apache-2.0）的 `perf` 能力，提供 Web 化的大模型推理性能压测：

用户选择平台上已注册/已部署的模型 → 配置压测参数（并发、请求数、输入输出长度、数据集类型）→ 后台异步执行 → 实时查看进度 → 结束后查看 TTFT/TPOT/吞吐/成功率等指标与图表。

## 核心价值
1. **不用再上命令行**：EvalScope 本身是 CLI 工具，运维/开发要记一堆参数；平台化后点选即可
2. **压测对象已在平台内**：模型已在「模型管理」注册，无需重复填 URL 和 Key —— 直接下拉选择
3. **结果可对比、可留存**：每次压测结果入库，支持同一模型不同配置横向对比、历史趋势
4. **和部署/量化闭环**：量化模型部署后一键压测，验证量化是否掉性能

## 功能边界（基于 evalscope perf 实测能力）

### 压测模式
| 模式 | 说明 | 对应 evalscope 参数 |
|------|------|---------------------|
| 闭环并发 | 固定并发数打满，请求数固定 | `parallel` + `number` |
| 开环限速 | 按目标 RPS 发请求 | `open_loop=true` + `rate` |
| SLA 自动调压 | 自动逐级加压，找到满足延迟 SLA 的最大并发 | `sla_auto_tune=true` |
| 多轮对话 | 多轮上下文压测 | `multi_turn=true` |

### 数据集类型（输入构造方式）
| 类型 | 说明 |
|------|------|
| `openqa` | 开放问答数据集（默认） |
| `random` | 按指定输入/输出 token 长度随机生成 |
| `line_by_line` | 每行一条 prompt |
| `share_gpt` | ShareGPT 真实对话 |
| `speed_benchmark` | 固定 prompt 测速 |
| `longalpaca` | 长上下文 |
| `custom` | 用户自定义上传 |

### 指标产出
- **TTFT**（首 token 时间）：均值 / P50 / P90 / P99
- **TPOT**（每 token 输出时间）
- **输出吞吐** output_throughput (tok/s)、**请求吞吐** request_throughput (req/s)
- **成功率** success_rate、错误分类统计
- 延迟百分位分布、输入/输出 token 统计

## 技术约束
- **License**：EvalScope 为 Apache-2.0，集成需保留版权声明与 NOTICE
- **Python**：evalscope 要求 `>=3.11`，平台后端为 3.12 ✅
- **依赖隔离**：evalscope 会连带 `modelscope[datasets]`、`pandas`、`nltk` 等框架依赖（数百 MB），**不能装进 api-server 镜像**
- **执行位置**：压测是纯 HTTP 负载生成，**不需要 GPU**，可跑普通 worker
- **执行时长**：单次压测从数十秒到数十分钟不等，必须异步 + 可中断
- **并发规模**：受 worker 进程数与网络限制，平台侧需设上限

## 与现有模块的关系
| 现有模块 | 关系 |
|----------|------|
| 模型管理 | 压测目标从模型列表选择，复用 `api_base_url` 与 `api_key` |
| 模型部署 | 部署完成的模型可直接压测，验证性能 |
| 模型量化 | 量化前后压测对比，量化收益量化评估 |
| Token 统计 | 压测产生的请求会计入网关用量（需明确是否排除） |

## 期望产出
- 「模型压测」Web 管理界面（列表 / 创建 / 实时进度 / 结果详情）
- 压测执行 worker（独立容器，队列隔离）
- 压测结果数据模型与历史对比
- 与模型管理的联动（一键对某模型发起压测）
