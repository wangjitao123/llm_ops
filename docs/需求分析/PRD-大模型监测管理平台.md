## 1. 需求概述

### 1.1 需求背景
随着企业内大模型应用的快速发展，各部门纷纷接入各类大模型（DeepSeek、GPT、通义千问、文心一言等），但缺乏统一的接入管理、鉴权、监控和成本管控体系。当前面临的主要问题包括：
- **模型接入分散**：各应用各自对接不同模型厂商，缺乏统一入口
- **Key 管理混乱**：API Key 人工管理，存在泄露和滥用风险
- **成本不可控**：Token 用量无统一统计，费用难以分摊到各业务线
- **缺乏监控告警**：模型异常、用量超限无法及时发现
- **微调能力缺失**：模型微调缺乏统一平台支持

### 1.2 需求目标

| 目标类型 | 目标描述 | 衡量指标 |
|----------|----------|----------|
| 业务目标 | 统一管理企业内所有大模型接入 | 覆盖 ≥ 90% 的模型接入场景 |
| 业务目标 | 精细化管控 API 调用成本 | 费用透明化，按部门/应用分摊 |
| 用户目标 | 开发者快速接入与获取 Key | 自助申请 Key 时间 < 5 分钟 |
| 用户目标 | 运维人员实时监控模型状态 | 异常发现时间 < 1 分钟 |
| 技术目标 | 网关平均响应延迟 < 5ms | 网关自身开销 |

### 1.3 预期收益
- **直接收益**: 降低 API Key 管理成本，防止 Key 滥用和泄露
- **间接收益**: 通过 Token 用量分析优化模型选型，降低调用成本 20-30%
- **管理收益**: 统一的门户实现模型、Key、费用、微调的全生命周期管理

### 3.2 功能详情

#### F-001: 总览大屏 Dashboard

**功能描述**: 提供全局概览视图，展示关键指标和趋势。

**业务规则**:
- 统计卡片展示：已接入模型数、活跃 Key 数、今日 Token 用量、今日请求量
- Token 用量趋势图：支持近 7 天/30 天/自定义时间范围切换
- 模型调用分布：按模型展示调用占比
- 模型运行状态列表：实时状态、响应时间、QPS
- 最近请求日志：实时滚动展示

**输入输出**:
| 输入 | 输出 | 说明 |
|------|------|------|
| 时间范围选择 | Token 趋势图 | 聚合统计 |
| 无 | 统计卡片数据 | 实时刷新 |

**边界条件**:
- 数据为空时展示占位提示
- 趋势图数据点不足时展示已有数据

#### F-002: 模型接入与配置

**功能描述**: 支持接入多种大模型并提供统一配置界面。

**业务规则**:
- 支持配置：模型名称、API 地址、API Key、QPS 上限、超时时间、模型权重
- 模型权重用于网关负载均衡时的加权轮询
- 支持模型启停控制
- 预设常见模型模板（DeepSeek、GPT、通义千问、文心一言、Claude、Gemini）

**异常处理**:
| 异常场景 | 处理方式 | 用户提示 |
|----------|----------|----------|
| 配置的 API 地址不可达 | 保存时进行连通性测试 | "模型 API 不可达，请检查地址" |
| QPS 配置超过默认上限 | 保存时提示 | "建议 QPS 不超过 500" |

---

#### F-003: 模型状态监控

**功能描述**: 实时监控各模型运行状态，包括在线/离线、响应时间、QPS、错误率等指标。

**业务规则**:
- 健康检查：每 30 秒向模型 API 发送心跳请求，连续 3 次失败判定为离线
- 延迟阈值：< 500ms 正常，500ms-2s 高延迟，> 2s 严重延迟
- 状态类型：在线（正常响应）、高延迟（响应时间超过阈值）、离线（心跳失败）、待配置（未完成初始化）
- 模型离线时自动触发告警通知（钉钉推送）
- 离线模型恢复后自动更新状态，通知管理员

**异常处理**:
| 异常场景 | 处理方式 |
|----------|----------|
| 模型连续 3 次心跳失败 | 标记为离线，触发告警，停止路由到该模型 |
| 模型响应时间连续 5 分钟 > 2s | 标记为严重延迟，触发告警 |
| 模型自动恢复 | 状态更新为在线，发送恢复通知 |

---

#### F-004: 模型版本管理

**功能描述**: 管理模型的不同版本，支持版本切换和回滚。

**业务规则**:
- 版本信息：版本号、发布时间、状态（当前/历史）、变更说明
- 当前正在使用的版本标记为"当前"
- 支持回滚到任意历史版本，回滚后原版本标记为"历史"
- 新版本接入时自动保留上一个版本
- 最多保留 10 个历史版本

---

#### F-005: API Key 生成与分发

**功能描述**: 为应用/用户生成 API Key，支持权限控制。

**业务规则**:
- Key 生成规则：`sk-` 前缀 + 随机字符串
- 支持配置：Key 名称、关联应用、可调用模型列表、速率限制、Token 上限、过期时间
- 支持 Key 的启用/禁用/回收操作
- 单应用可生成多个 Key
- Key 生成后仅展示一次完整密钥，后续只显示脱敏形式

**异常处理**:
| 异常场景 | 处理方式 |
|----------|----------|
| Key 达到过期时间 | 自动禁用，发送通知 |
| 单 Key 速率超限 | 返回 429，记录日志 |

---

#### F-006: Key 权限与速率控制

**功能描述**: 控制每个 Key 的模型访问权限和调用速率限制。

**业务规则**:
- 每个 Key 可关联一个或多个可调用模型
- 速率限制维度：每秒（QPS）、每分钟（RPM）、每日（RPD）
- 速率限制分两级：全局默认限制 + 单 Key 自定义限制，取更严格者生效
- Key 的 Token 上限：达到上限后自动禁用，次月或手动重置

---

#### F-007: Key 生命周期管理

**功能描述**: 管理 Key 从创建到回收的完整生命周期。

**业务规则**:
- 状态流转：启用 → 禁用（手动）/ 过期（自动）→ 回收（删除）
- 过期前 7 天发送到期提醒通知
- 过期后自动禁用，保留数据 30 天后可恢复
- 回收的 Key 不可恢复，数据保留 90 天后彻底删除
- 操作记录写入审计日志

---

#### F-008: Token 用量实时统计

**功能描述**: 实时统计 Token 用量，支持多维度下钻查看。

**业务规则**:
- 统计维度：按模型、按应用、按用户（三个维度可交叉筛选）
- 统计指标：输入 Token 数、输出 Token 数、总计 Token 数、请求次数
- 数据刷新延迟：< 30s（近实时）
- 时间范围：近 24 小时、近 7 天、近 30 天、自定义
- 支持图表展示：趋势折线图、占比环形图

---

#### F-009: 多维度费用报表

**功能描述**: 根据 Token 用量计算费用，生成多维度报表，支持导出。

**业务规则**:
- 费用计算公式：各模型 Token 消耗 × 该模型单价，累加
- 支持按模型、应用、用户维度查看费用明细
- 报表导出格式：CSV / Excel
- 统计数据准确性：99.99%（基于日志重算校验）

---

#### F-010: 用量预警规则

**功能描述**: 设置预警阈值，当用量或费用超过阈值时触发通知。

**业务规则**:
- 预警维度：日 Token 用量、月 Token 用量、日费用、月费用
- 阈值支持固定值和百分比两种模式
- 通知方式：钉钉机器人推送、Webhook
- 预警级别：警告（达到 80% 阈值）、严重（达到 100% 阈值）
- 同一规则 24 小时内最多触发 3 次告警，避免重复通知

---

#### F-011: 统一 API 路由

**功能描述**: 作为统一入口，根据路由规则分发请求到不同后端模型服务。

**业务规则**:
- 支持路由策略：加权轮询、主备切换、单点
- 路由匹配规则：基于请求路径（如 `/v1/chat/completions`）
- 协议转换：将统一格式的请求转换为各厂商 API 格式
- 响应格式统一化：将各厂商响应转换为统一格式

**异常处理**:
| 异常场景 | 处理方式 |
|----------|----------|
| 目标模型不可用 | 自动切换备用模型（主备模式） |
| 所有模型均不可用 | 返回 503，记录告警 |

---

#### F-012: 请求鉴权与限流

**功能描述**: 对每个 API 请求进行鉴权和速率限制。

**业务规则**:
- 鉴权流程：提取请求头中的 API Key → 校验 Key 有效性 → 校验模型访问权限 → 校验速率限制
- 全局限流：共享 Token Bucket 算法，全局 QPS 上限可配置
- 单 Key 限流：独立 Token Bucket 算法，单 Key QPS 上限可配置
- 限流响应：HTTP 429 + 响应头 `Retry-After`
- 鉴权失败的请求不计数（不计入限流统计）

**异常处理**:
| 异常场景 | 处理方式 | 响应 |
|----------|----------|------|
| API Key 无效 | 返回 401 | "Invalid API Key" |
| 无权限访问模型 | 返回 403 | "No permission to access this model" |
| 速率超限 | 返回 429 | "Rate limit exceeded, retry after N seconds" |

#### F-013: 请求日志与审计

**功能描述**: 记录所有 API 请求的完整日志，支持查询、审计和导出。

**业务规则**:
- 日志字段：请求时间、请求 ID、API Key 名称、应用、模型、请求路径、输入 Token 数、输出 Token 数、响应时间、状态码、来源 IP
- 日志存储：活跃数据保留 30 天（快速查询），归档数据保留 180 天（可导出查询）
- 日志不丢不重：基于消息队列 + 批量写入，确保日志完整性
- 支持按时间、状态、应用、模型筛选
- 支持导出为 CSV 格式

---

#### F-014: 微调任务管理

**功能描述**: 创建、监控和管理模型微调任务。

**业务规则**:
- 创建任务需指定：任务名称、基座模型、训练数据集、验证数据集（可选）
- 超参数配置：训练轮数、学习率、批次大小、最大序列长度
- 完整状态机：待运行 → 排队中 → 运行中 → 暂停（手动）→ 已完成 / 失败 / 已取消
  - 待运行 → 排队中：资源检查通过后进入队列
  - 排队中 → 运行中：资源分配就绪后开始训练
  - 运行中 → 暂停：用户手动暂停
  - 暂停 → 运行中：用户手动恢复
  - 运行中 → 已完成：训练正常结束
  - 运行中 → 失败：训练异常终止
  - 排队中/暂停 → 已取消：用户手动取消
- 任务完成后可部署为新的模型版本（F-004）
- 部署后状态更新为"已部署"

#### F-015: 数据集管理

**功能描述**: 上传、标注、版本管理微调训练数据集。

**业务规则**:
- 支持格式：JSONL、CSV、JSON、Parquet
- 单文件最大 500MB
- 数据集版本管理，支持版本回退
- 标注状态管理：待标注 → 标注中 → 已标注 → 待审核 → 已审核

#### F-016: 微调结果评估

**功能描述**: 评估微调后模型的效果，与基座模型进行多维度对比。

**业务规则**:
- 评估指标：准确率（Accuracy）、BLEU 分数、ROUGE-L、推理延迟
- 对比方式：微调前 vs 微调后，同数据集评估
- 结果展示：表格 + 趋势图
- 评估报告可导出

---

#### F-017: 模型对比评估

**功能描述**: 多维度对比不同模型的质量、成本和性能。

**业务规则**:
- 对比维度：响应质量评分、平均延迟、Token 成本、上下文长度、多模态能力、中文理解、代码生成
- 综合评分算法：基于各维度加权计算
- 提供推荐建议：根据场景推荐最优模型

#### F-018: SSO 统一认证

**功能描述**: 对接公司 SSO 系统，实现统一登录认证。（优先级：Must — 系统登录前置条件）

**业务规则**:
- 对接方式：支持 OAuth2 / SAML / LDAP / CAS 协议（待 Q-002 确认具体方式）
- 用户认证流程：用户访问系统 → 跳转 SSO 登录页 → SSO 认证通过 → 回调获取用户信息 → 创建/更新本地会话
- 本平台不维护独立用户体系，用户信息由 SSO 同步
- 会话管理：JWT Token，有效期 24 小时，支持刷新
- 角色映射：SSO 用户组 → 平台角色（管理员/普通用户）

---

#### F-019: 钉钉通知推送

**功能描述**: 通过钉钉机器人发送系统告警和通知到指定群聊或个人。

**业务规则**:
- 配置项：Webhook URL、加签密钥、@指定手机号、@所有人
- 通知事件：Token 用量预警、模型异常、微调任务完成/失败
- 消息格式：Markdown，包含事件标题、详情、发生时间、处理建议
- 支持配置多个 Webhook URL（区分开发/测试/生产环境）

---

#### F-020: 操作日志审计

**功能描述**: 记录所有用户的关键操作，支持查询和导出。

**业务规则**:
- 记录范围：Key 创建/禁用/回收、模型配置变更、路由规则修改、系统配置变更、用户登录/登出
- 日志字段：操作时间、操作用户、操作类型、操作详情、来源 IP、操作结果
- 日志保存 180 天
- 支持按时间、用户、操作类型筛选
- 支持导出为 CSV 格式

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 | 测试方法 |
|------|------|----------|
| 网关代理延迟 | < 5ms（不含模型调用） | 压测 |
| 页面加载时间 | < 2s | 浏览器性能测试 |
| 并发用户数 | ≥ 200 | 压测 |
| 数据刷新延迟 | < 30s（统计看板） | 端到端测试 |
| 日处理请求量 | ≥ 1000 万次 | 容量测试 |

### 4.2 安全需求

| 安全项 | 要求 |
|--------|------|
| 认证方式 | 对接公司 SSO，统一认证 |
| 鉴权机制 | API Key 鉴权 + JWT Token |
| 数据安全 | API Key 加密存储，传输启用 HTTPS |
| 审计日志 | 所有关键操作记录审计日志，保存 180 天 |
| 速率限制 | 支持全局/单 Key 两级限流 |

### 4.3 数据一致性与容灾

| 指标 | 要求 |
|------|------|
| 日志完整性 | 网关请求日志不丢不重，基于消息队列保障 |
| 统计准确性 | Token 统计数据准确性 ≥ 99.99%（基于日志重算校验） |
| RTO（恢复时间目标） | ≤ 30 分钟 |
| RPO（恢复点目标） | ≤ 5 分钟 |
| 数据持久化 | 统计数据和日志持久化存储，支持冷热分离 |

### 4.4 可用性需求

| 指标 | 要求 |
|------|------|
| 系统可用性 | ≥ 99.9% |
| 网关高可用 | 多节点部署，故障自动切换 |
| 数据持久性 | 统计数据和日志持久化存储 |

## 6. 验收标准

### 6.1 核心功能验收

```gherkin
Feature: 模型接入
  Scenario: 成功接入新模型
    Given 管理员在模型管理页面
    When 填写模型名称、API 地址、API Key 等信息
    And 点击保存
    Then 模型出现在模型列表中
    And 状态显示为"待配置"

  Scenario: 编辑模型配置
    Given 已有已接入的模型
    When 管理员点击编辑按钮
    And 修改模型配置参数
    And 点击保存
    Then 模型配置更新成功
    And 新配置立即生效

  Scenario: 停用模型
    Given 模型当前为"在线"状态
    When 管理员点击停用按钮
    Then 模型状态变为"离线"
    And 网关不再路由请求到该模型

Feature: 模型状态监控
  Scenario: 模型离线自动检测
    Given 模型处于在线状态
    When 连续 3 次心跳检测失败
    Then 模型状态更新为"离线"
    And 触发钉钉告警通知
    And 网关停止路由到该模型

Feature: API Key 生成
  Scenario: 生成新的 API Key
    Given 管理员在 Key 管理页面
    When 填写 Key 名称、关联应用、权限配置
    And 点击生成
    Then 系统生成新 Key
    And 页面展示完整 Key 一次
    And 刷新后 Key 显示为脱敏格式

  Scenario: 禁用 API Key
    Given 某个 Key 为"启用"状态
    When 管理员点击禁用按钮
    Then Key 状态变为"已禁用"
    And 使用该 Key 的请求被拒绝

Feature: Token 用量预警
  Scenario: 触发用量预警
    Given 预警规则已配置（日用量 >= 1,000,000 Token）
    When 当日 Token 用量达到 1,000,000
    Then 系统触发预警通知
    And 钉钉机器人推送告警消息

Feature: 统一网关
  Scenario: 通过网关调用模型
    Given 应用已配置有效的 API Key
    When 向统一网关发送 /v1/chat/completions 请求
    And 请求包含有效 Key 和消息内容
    Then 网关路由到目标模型
    And 返回统一格式的响应

  Scenario: 无效 Key 请求被拒绝
    Given 请求携带无效的 API Key
    When 向统一网关发送请求
    Then 返回 401 Unauthorized
    And 请求日志记录认证失败

  Scenario: 请求被限流
    Given 单 Key 速率限制为 100/min
    When 该 Key 在 1 分钟内发送第 101 个请求
    Then 返回 429 Too Many Requests
    And 响应头包含 Retry-After

Feature: 微调任务管理
  Scenario: 创建微调任务
    Given 已上传训练数据集
    When 数据科学家填写任务名称、选择基座模型和数据集
    And 配置超参数
    And 点击"开始训练"
    Then 微调任务创建成功
    And 任务状态为"运行中"或"排队中"

Feature: SSO 统一认证
  Scenario: 通过 SSO 登录系统
    Given 用户未登录
    When 访问系统首页
    Then 跳转到公司 SSO 登录页
    When SSO 认证通过
    Then 用户成功登录系统
    And 展示用户信息

Feature: 钉钉通知推送
  Scenario: 配置钉钉机器人
    Given 管理员在系统配置页面
    When 填写钉钉机器人 Webhook URL
    And 选择通知事件
    And 点击保存
    Then 钉钉机器人配置生效

  Scenario: 测试推送
    Given 已配置钉钉机器人
    When 管理员点击"测试推送"按钮
    Then 钉钉群收到测试消息
```
