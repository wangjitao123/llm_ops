### US-001: 模型统一管理

**基本信息**
- **优先级**: MoSCoW - Must
- **故事点**: 8
- **所属Epic**: 核心管理

**用户故事**
**作为** 平台管理员
**我想要** 在平台上统一接入和管理多种大模型（DeepSeek、GPT、通义千问、文心一言等）
**以便于** 集中管控企业内所有模型资源，统一配置和监控

**验收条件**
```gherkin
Scenario: 接入新模型
  Given 管理员在模型管理页面
  When 点击"接入模型"按钮
  And 填写模型名称、API 地址、API Key、QPS 上限等配置信息
  And 点击保存
  Then 模型出现在模型列表中
  And 状态显示为"在线"或"待配置"

Scenario: 编辑模型配置
  Given 已有已接入的模型
  When 管理员点击编辑按钮
  And 修改模型配置参数
  And 点击保存
  Then 模型配置更新成功
  And 新配置立即生效

Scenario: 停用模型
  Given 模型当前为"在线"状态
  When 管理员点击停用按钮
  Then 模型状态变为"离线"
  And 网关不再路由请求到该模型
```

**INVEST 检查**
| 检查项 | 符合 | 说明 |
|--------|------|------|
| Independent | ✓ | 不依赖其他故事 |
| Negotiable | ✓ | 模型配置项可协商 |
| Valuable | ✓ | 统一管理模型，减少重复工作 |
| Estimable | ✓ | 可估算工作量 |
| Small | ✗ | 较大，建议拆分为子任务 |
| Testable | ✓ | 可编写测试用例 |

### US-002: API Key 自助申请

**基本信息**
- **优先级**: MoSCoW - Must
- **故事点**: 5
- **所属Epic**: 核心管理

**用户故事**
**作为** 应用开发者
**我想要** 在平台上自助申请 API Key，并配置可调用的模型和速率限制
**以便于** 快速接入 AI 能力，无需等待管理员手动分配

**验收条件**
```gherkin
Scenario: 生成新的 API Key
  Given 管理员在 Key 管理页面
  When 填写 Key 名称、关联应用、可调用模型、速率限制
  And 点击"生成 Key"
  Then 系统生成一个以 "sk-" 开头的 API Key
  And 页面展示完整 Key（仅一次）
  And Key 自动关联到指定应用和模型

Scenario: 查看 Key 列表
  Given 已有多个 API Key
  When 管理员进入 Key 管理页面
  Then 展示所有 Key 的脱敏形式
  And 显示状态、速率限制、已用 Token、过期时间

Scenario: 禁用 API Key
  Given 某个 Key 为"启用"状态
  When 管理员点击禁用按钮
  Then Key 状态变为"已禁用"
  And 使用该 Key 的请求被拒绝
```

Scenario: 设置用量预警
  Given 管理员在预警规则设置页面
  When 设置日用量阈值和通知方式
  And 点击保存
  Then 当用量达到阈值时自动触发告警通知

### US-004: 统一网关调用

**基本信息**
- **优先级**: MoSCoW - Must
- **故事点**: 13
- **所属Epic**: 核心管理

**用户故事**
**作为** 应用开发者
**我想要** 通过统一网关调用各种大模型，而不需要关心各厂商的 API 差异
**以便于** 降低接入成本，实现模型的无缝切换

**验收条件**
```gherkin
Scenario: 通过网关调用模型
  Given 应用已配置有效的 API Key
  When 向统一网关发送 /v1/chat/completions 请求
  And 请求包含有效 Key 和消息内容
  Then 网关路由到目标模型
  And 返回统一格式的响应

Scenario: 请求被限流
  Given 单 Key 速率限制为 100/min
  When 该 Key 在 1 分钟内发送第 101 个请求
  Then 返回 429 Too Many Requests
  And 响应头包含 Retry-After

Scenario: 查看请求日志
  Given 已有 API 请求记录
  When 管理员进入网关请求日志页面
  Then 展示请求时间、应用、模型、Token 数、状态
  And 支持按时间/状态筛选
```

### US-005: 模型微调管理

**基本信息**
- **优先级**: MoSCoW - Should
- **故事点**: 8
- **所属Epic**: 进阶能力

**用户故事**
**作为** 数据科学家
**我想要** 在平台上创建和管理模型微调任务
**以便于** 针对特定业务场景优化模型效果

**验收条件**
```gherkin
Scenario: 创建微调任务
  Given 已上传训练数据集
  When 数据科学家填写任务名称、选择基座模型和数据集
  And 配置超参数（Epochs、Learning Rate、Batch Size 等）
  And 点击"开始训练"
  Then 微调任务创建成功
  And 状态显示为"运行中"

Scenario: 查看微调进度
  Given 微调任务正在运行
  When 数据科学家查看任务详情
  Then 显示训练进度百分比
  And 显示当前训练轮次和损失值

Scenario: 部署微调模型
  Given 微调任务已完成
  When 数据科学家点击"部署"按钮
  Then 微调后的模型作为新版本发布
  And 可在模型管理中选择该版本
```

### US-007: 用量预警通知

**基本信息**
- **优先级**: MoSCoW - Should
- **故事点**: 3
- **所属Epic**: Token 统计

**用户故事**
**作为** 平台管理员
**我想要** 设置用量预警规则，当 Token 用量或费用超过阈值时收到通知
**以便于** 及时应对突发情况，避免超预算

**验收条件**
```gherkin
Scenario: 配置预警规则
  Given 管理员在预警规则设置页面
  When 设置日用量阈值、月费用阈值和通知方式
  And 点击保存
  Then 预警规则生效
  And 当超过阈值时触发通知

Scenario: 收到预警通知
  Given 已配置预警规则
  When Token 用量达到阈值的 100%
  Then 钉钉机器人推送告警消息
  And 消息包含当前用量和阈值信息
```
