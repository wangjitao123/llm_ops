- 日期：2026-09-10

## 1. 现状与缺口

**已有**：`model_eval` 表 + CRUD API + 前端列表/创建/查看详情 → 创建评估入库，但 `result`/`recommendation` 永远空，状态永远 `pending`（"待配置"）。

**缺口**：没有"跑评测"的逻辑——选中两个模型后，系统不会自动发测试题、不会算评分、不会出推荐。

## 2. 变更方案（轻量版）

### 新增后端模块 `app/services/eval_runner.py`

核心流程：
```
用户点击"开始评估"
      ↓
POST /api/v1/compare/{id}/run
      ↓
读取 eval（获取 model_ids）
      ↓
对每个模型：
  依次发送 5 条预设测试题（非流式，用系统内调用）
  记录每条请求的：耗时 / prompt_tokens / completion_tokens / finish_reason
      ↓
计算各维度分：
  延迟 latency        → 平均响应时间 ms（越低越好，0~100 归一化）
  吞吐量 throughput   → tokens/秒（越高越好）
  稳定性 stability    → 响应时间的变异系数（越低越好）
  上下文 context      → finish_reason == 'length' 的比例（越低越好）
  成本 cost           → 按总 token 数归一化对比（模型间相对评分）
  质量 quality        → 标记"待人工评测"（分数 0，用户可手动在结果页修改）
  易用性 ease_of_use  → 标记"待人工评测"
      ↓
加权综合分 = Σ(维度分 × 权重%)
      ↓
出推荐建议
      ↓
写入 model_eval.result + model_eval.recommendation
状态 → completed
```

### 测试题集（硬编码 5 条，客服场景）

贴合用户刚建的"客服场景模型测试"，直接让对话有意义：

```
1. {"role":"user","content":"你好，我想查询一下我的订单到了哪里"}
2. {"role":"user","content":"我想退货退款，怎么操作"}
3. {"role":"user","content":"你们的营业时间是几点到几点"}
4. {"role":"user","content":"我昨天买的东西今天可以送到吗"}
5. {"role":"user","content":"怎么联系人工客服"}
```

### 评分算法（关键）

每个维度归一化到 0-100 分，以保证适用不限两个模型的情况：

| 维度 | 原始指标 | 归一化方式 |
|------|---------|-----------|
| latency | 各模型平均延迟 ms | `min/max` 归一化后 `100 - (x-min)/(max-min)*100`（延迟越低分越高） |
| throughput | tokens/秒 | `(x-min)/(max-min)*100`（吞吐越高分越高） |
| stability | 延迟变异系数 CV | `(1 - CV)*100`，最低保底 0 |
| context | finish_reason='length' 占比 | `(1 - ratio)*100` |
| cost | 总 token 数 | `(min/x)*100`（token 越少成本越低分越高） |
| quality | — | 0，标记 `need_human` |
| ease_of_use | — | 0，标记 `need_human` |

**加权总分** = Σ(各维度分 × 对应权重) / Σ(已计算维度的权重和) —— 只算有数据的维度，quality 和 ease_of_use 不参与计算。

### 新增 API

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/v1/compare/{id}/run` | 触发评测（同步执行，返回结果） |
| `PATCH` | `/api/v1/compare/{id}/result` | 手动修改/补充评分（如用户填 quality 分） |

## 4. 风险与边界

| 风险 | 说明 | 对策 |
|------|------|------|
| 同步执行耗时长 | 每个模型 × 5 条请求（非流式），2 个模型约 5-15 秒 | 前端显示加载中 + 进度提示；后续可改为异步任务 |
| 模型不可用/报错 | 某模型连不上 | 跳过该模型，错误信息写入 `result.errors`，不影响其他模型 |
| 无单价配置 | cost 维度的"钱"只能是相对分，不能按元计价 | 文档说明；后续 model 表加 price 字段后完全自动化 |
| quality 人工未补 | 总分只基于 5 个客观维度（占权重 60%） | 总分旁加脚注说明不包含质量/易用性 |
