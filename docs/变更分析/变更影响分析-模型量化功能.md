## 二、可行性分析

### 2.1 现有平台架构限制

当前平台的核心定位是 **API 代理网关 + 模型管理后台**：
- 所有模型以 API 接口形式接入（配置 `api_base_url` + `api_key`）
- 平台不加载模型权重、不运行推理
- 服务器 `10.51.13.7` 为 CPU 服务器（未发现 NVIDIA GPU）
- Docker 部署无 GPU passthrough 配置

### 2.2 量化对基础设施的要求

| 工具 | GPU 内存需求（7B模型） | 安装依赖 |
|------|----------------------|---------|
| llm-compressor (GPTQ) | ~16GB | PyTorch + CUDA 12+ |
| AutoAWQ | ~14GB | PyTorch + CUDA |
| AutoGPTQ | ~14GB | PyTorch + CUDA |
| 原生 transformers + bitsandbytes | ~10GB（4bit）| bitsandbytes |

> 结论：**当前服务器无法运行量化**。量化需要单独的 GPU 算力。

### 2.3 可行方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A. 平台侧量化管理器（推荐）** | 平台做配置+编排+追踪，量化脚本在外部GPU机器或云上执行 | 不依赖平台GPU、逻辑清晰、可复用现有任务管理模式 | 外部执行需手动介入 |
| **B. 集成GPU量化容器** | 新增 GPU-enabled Docker 服务，平台触发量化任务 | 全自动化、体验好 | 需要 GPU 服务器、依赖体积大（10G+）|
| **C. HuggingFace Spaces / AutoTrain** | 调用 HuggingFace 云端量化 API | 零硬件成本 | 需要外网、依赖第三方服务稳定性 |

### 2.4 推荐方案

**方案 A：平台侧量化管理器（轻量化）**

核心思路：**平台管「配置→编排→注册」，量化执行放外部**。

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  平台 UI     │     │ 量化脚本     │     │  GPU 机器    │
│  1.选基座模型 ├────►│  (生成导出)   ├────►│  (执行量化)   │
│  2.配参数     │     │              │     │              │
│  3.提交任务   │     │              │     │  4.产出模型   │
│              │◄────│              │◄────│  5.上传结果   │
│  6.注册模型   │     │              │     │              │
└──────────────┘     └──────────────┘     └──────────────┘
```

### 3.2 量化配置参数

| 参数 | 说明 | 默认值 | 可选值 |
|------|------|--------|--------|
| 基座模型 | HuggingFace 模型 ID | - | 如 Qwen/Qwen2.5-7B |
| 量化算法 | 核心量化方法 | GPTQ | GPTQ / AWQ / bitsandbytes |
| 权重精度 | 权重比特数 | 4-bit | 2 / 3 / 4 / 8 |
| 激活精度 | 激活值比特数 | 16-bit | 8 / 16 |
| 校准数据集 | 代表场景的小样本集 | None（默认256条） | 可选上传自定义数据集 |
| 校准样本数 | 校准用的样本条数 | 256 | 64~1024 |
| 分组大小 | 量化分组粒度 | 128 | 32 / 64 / 128 |
| 模型输出路径 | 量化后模型保存路径 | default | 自定义路径或HF仓库 |

### 3.3 页面流程

```
模型管理 → 量化任务 → 创建任务（配置参数）
                    → 导出脚本 → 在GPU机器执行
```

## 五、技术方案

### 5.1 脚本生成示例（以 llm-compressor 为例）

用户选择配置后，平台自动生成如下脚本供下载执行：

```python
#!/usr/bin/env python3
"""量化脚本 - 由大模型监测平台自动生成"""
from transformers import AutoModelForCausalLM, AutoTokenizer
from llmcompressor import compress
import torch

model_id = "{base_model_id}"
model = AutoModelForCausalLM.from_pretrained(
    model_id, torch_dtype=torch.float16, device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained(model_id)

# 校准数据集
calibration_data = [...]  # 256条样本

# 执行量化
compressed_model = compress(
    model,
    tokenizer=tokenizer,
    calibration_data=calibration_data,
    algorithm="{algorithm}",
    target_bit_width={weight_bits},
    group_size={group_size},
)

# 保存
compressed_model.save_pretrained("{output_path}")
tokenizer.save_pretrained("{output_path}")
print("量化完成！模型已保存至：{output_path}")
```

### 5.2 量化结果注册流程

1. 用户在外 GPU 机器执行脚本
2. 量化完成后，用户上传结果（HF模型ID 或 下载链接）
3. 平台创建新 Model 记录：
   - provider = `quantized`
   - api_base_url = 量化后模型存放路径
   - version = `{原始版本}-q{w_bits}a{a_bits}-{algorithm}`

## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 服务器无 GPU | 必然 | 量化不能在平台内运行 | 采用脚本导出模式 |
| 量化工具依赖版本冲突 | 中 | 脚本运行失败 | 在脚本中固定依赖版本 |
| HF 模型下载失败 | 中 | 量化无法开始 | 支持本地路径+代理下载 |
| 量化后模型文件过大 | 低 | 上传困难 | 支持 HF Hub 直接推送 |
