## 1. 系统概述

模型部署模块负责管理平台中所有模型推理端点的生命周期（注册、部署、启停、监控、配置）以及与现有模型管理和网关的自动集成。

### 1.1 系统边界

```
┌─────────────────────────────────────────────────┐
│                 模型部署模块                       │
│                                                   │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐       │
│  │ 端点注册   │  │ 自动部署   │  │ 健康监控   │       │
│  │ (M01)    │  │ (M02)    │  │ (M04)    │       │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘       │
│       │              │              │             │
│  ┌────▼──────────────▼──────────────▼─────┐       │
│  │         配置管理 (M03)                    │       │
│  │  ToolCall / SystemPrompt / WebSearch     │       │
│  └────────────────┬────────────────────────┘       │
│                   │                                │
│          ┌────────▼────────┐                       │
│          │  集成对接 (M05)  │                       │
│          │  模型管理 / 网关  │                       │
│          └─────────────────┘                       │

```

### 1.2 外部依赖

| 依赖模块 | 关系 | 接口 |
|----------|------|------|
| 模型量化模块 | 提供量化完成的模型路径列表 | REST API (获取已完成量化列表) |
| 模型管理模块 | 自动注册部署为模型记录 | REST API (创建/更新/删除模型) |
| 统一网关 | 转发请求时注入配置 | 共享数据库 / 缓存 |
| Docker Daemon | 新建部署时拉取容器 | Docker SDK / Docker API |

## 2. 系统指标

### 2.1 用户规模

| 指标 | 数值 | 说明 |
|------|------|------|
| 平台管理员 | 2-5 人 | 管理所有部署 |
| AI 工程师 | 5-20 人 | 注册自己的模型和配置 |
| 运维人员 | 2-3 人 | 监控和诊断 |
| **总用户数** | **~30 人** | 内部平台，非外部用户 |

### 2.2 业务规模

| 指标 | 数值 | 说明 |
|------|------|------|
| 最大同时运行部署数 | ≤ 20 | 8×L20 GPU，每卡最多 2-3 个 7B 模型 |
| 日新增注册 | ≤ 5 | 大部分为已有端点注册 |
| 日新增部署 | ≤ 3 | 新建部署操作频率低 |
| 配置变更 | ≤ 20 次/天 | 非高频操作 |
| 健康检查请求 | ~8.6 万次/天 | 20 个端点 × 2880 次/天(30s间隔) |

### 2.3 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 页面加载 | < 2s | 部署列表页 |
| 配置保存 | < 1s | 配置生效 |
| 健康检查间隔 | 30s | 可配置 |
| 健康检查 HTTP 超时 | 5s | 超过 5s 视为失败 |
| 部署到就绪 | < 5min(7B) | 包含模型加载时间 |
| 启停操作 | < 30s | Docker 容器操作 |

## 3. 容量规划

### 3.1 数据存储

| 数据表 | 估算记录数 | 单条大小 | 总大小 |
|--------|-----------|---------|--------|
| 部署配置表 | ≤ 100 | ~2KB | ~200KB |
| 部署配置版本记录 | ≤ 500 | ~1KB | ~500KB |
| 健康检查日志 | 20 端点 × 2880 次 = 5.7 万行/天 | ~200B | ~11MB/天 → ~400MB/年 |
| 性能指标(聚合) | 每 5 分钟聚合 = ~13 万行/年 | ~100B | ~13MB/年 |

### 3.2 GPU 资源规划

| 资源 | 容量 | 规划 |
|------|------|------|
| GPU | 8 × NVIDIA L20 (48GB) | 单卡可承载 2-3 个 7B 量化模型 |
| 显存 | 384GB 总计 | 7B GPTQ W4A16 ≈ 13-14GB/卡 |
| 部署上限 | ~20 个 7B 模型 | 或 ~8 个 14B / ~4 个 32B |

### 3.3 存储规划

| 存储类型 | 内容 | 预估大小 | 存储方式 |
|----------|------|---------|----------|
| 量化模型文件 | 量化后的 safetensors | 每个 7B 约 7-14GB | Docker volume `quantized_models` |
| 部署配置 | 数据库存储 | ~MB 级别 | PostgreSQL (已有) |
| 健康日志 | 数据库存储 | ~400MB/年 | PostgreSQL (已有) |

## 4. 技术选型

### 4.1 后端

| 技术 | 选型 | 理由 |
|------|------|------|
| Web 框架 | FastAPI (已有) | 与现有 api-server 一致 |
| 数据库 | PostgreSQL + SQLAlchemy async (已有) | 与现有平台一致 |
| 消息队列 | RabbitMQ / Celery (已有) | 部署任务的异步执行 |
| Docker SDK | `docker-py` | 管理容器生命周期 |
| 推理引擎 | vLLM (首选) | GPTQ/AWQ 支持最好，社区活跃 |
| 备选引擎 | TGI / SGLang | 用户可选 |

### 4.2 前端

| 技术 | 选型 | 理由 |
|------|------|------|
| 框架 | Vue 3 + Composition API (已有) | 与现有前端一致 |
| UI 库 | Ant Design Vue (已有) | 保持风格统一 |
| 组件复用 | 可参考 quantization 模块的表格/弹窗模式 | 相同的 CRUD 模式 |

## 5. 数据模型设计

### 5.1 部署配置表 (deployment)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | 主键 |
| name | varchar(128) | 部署名称 |
| deploy_type | enum('managed', 'conda', 'docker', 'other') | 运行方式 |
| status | enum('running', 'stopped', 'deploying', 'failed', 'deleted') | 状态 |
| base_model_id | int FK | 基座模型 ID (关联已有模型表) |
| hf_model_id | varchar(256) | HuggingFace 模型 ID (可选) |
| endpoint_url | varchar(512) | 端点 URL |
| engine | varchar(32) | 推理引擎 (vllm/tgi/sglang) |
| gpu_ids | int[] | GPU 编号列表 |
| gpu_count | int | GPU 数量 |
| gpu_memory_gb | float | 显存占用 |
| max_concurrency | int | 最大并发数 |
| max_input_tokens | int | 最大输入 Token |
| system_prompt | text | System Prompt 模板 |
| temperature | float | 采样参数 |
| top_p | float | 采样参数 |
| max_tokens | int | 最大输出 Token |
| frequency_penalty | float | 频率惩罚 |
| tools_json | jsonb | Tool Call 定义列表 |
| web_search_enabled | bool | 启用 Web Search |
| web_search_config | jsonb | 搜索配置 |
| env_vars | jsonb | 环境变量 |
| auto_register | bool | 自动注册到模型管理 |
| health_check_enabled | bool | 启用健康检查 |
| error_message | text | 错误信息 |
| created_by | varchar(64) | 创建人 |
| created_at | timestamp | 创建时间 |
| updated_at | timestamp | 更新时间 |

### 5.2 健康检查记录表 (deployment_health_log)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | 主键 |
| deployment_id | int FK | 关联部署 |
| status_code | int | HTTP 状态码 |
| latency_ms | int | 响应延迟 |
| checked_at | timestamp | 检查时间 |

### 5.3 性能指标聚合表 (deployment_metrics)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | 主键 |
| deployment_id | int FK | 关联部署 |
| qps | float | 平均 QPS |
| p50_latency_ms | float | P50 延迟 |
| p99_latency_ms | float | P99 延迟 |
| error_rate | float | 错误率 |
| window_start | timestamp | 统计窗口开始 |
| window_end | timestamp | 统计窗口结束 |

## 6. API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/v1/deployments | 部署列表（分页+筛选） |
| POST | /api/v1/deployments | 注册已有端点 |
| GET | /api/v1/deployments/{id} | 部署详情 |
| PUT | /api/v1/deployments/{id} | 更新配置 |
| DELETE | /api/v1/deployments/{id} | 删除部署 |
| POST | /api/v1/deployments/{id}/start | 启动部署 |
| POST | /api/v1/deployments/{id}/stop | 停止部署 |
| POST | /api/v1/deployments/{id}/restart | 重启部署 |
| POST | /api/v1/deployments/{id}/retry | 重试失败部署 |
| GET | /api/v1/deployments/{id}/logs | 获取部署日志 |
| GET | /api/v1/deployments/{id}/metrics | 获取性能指标 |
| GET | /api/v1/deployments/quantized-models | 获取量化完成的模型列表（用于新建部署） |
| GET | /api/v1/deployments/gpu-topology | 获取 GPU 资源拓扑 |
