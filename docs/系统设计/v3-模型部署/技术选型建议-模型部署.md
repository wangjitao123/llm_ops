# 技术选型建议 — 模型部署模块

## 1. 推理引擎选型

| 对比项 | vLLM | TGI | SGLang |
|--------|------|-----|--------|
| GPTQ 支持 | ✅ 原生支持 | ✅ 支持 | ⚠️ 试验性 |
| AWQ 支持 | ✅ 原生支持 | ⚠️ 部分 | ⚠️ 试验性 |
| PagedAttention | ✅ | ❌ | ✅ |
| 连续批处理 | ✅ | ✅ | ✅ |
| 社区活跃度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |
| Docker 镜像大小 | ~8GB | ~6GB | ~7GB |
| 端口兼容 | OpenAI API | OpenAI API | OpenAI API |

**建议**：先只支持 vLLM，TGI 和 SGLang 作为第二期可选项。

## 2. 后端技术选型

| 组件 | 技术 | 理由 |
|------|------|------|
| API 框架 | FastAPI (已有) | 保持一致 |
| ORM | SQLAlchemy async (已有) | 保持一致 |
| 任务队列 | Celery (已有) | 异步部署任务 |
| Docker 管理 | docker-py | 成熟的 Python Docker SDK |
| 数据库 | PostgreSQL (已有) | 保持一致 |

## 3. 健康检查方案

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| Celery 定时任务 | 分布式，与现有架构一致 | 调度延迟 ~秒级 | ✅ |
| asyncio 后台协程 | 低延迟 | 单进程，api-server 重启丢失 | ❌ |
| 独立健康检查服务 | 隔离性好 | 额外维护成本 | ❌ |

**建议**：使用 Celery Beat 定时任务，每 30 秒调度健康检查任务。

## 4. Docker 容器管理

| 容器名称规则 | 说明 |
|-------------|------|
| `dpl-{deployment_id}-{engine}-{port}` | 如 `dpl-12-vllm-31100` |
| 端口分配 | 从 31100 起顺序分配 |

## 5. 安全

| 安全项 | 方案 |
|--------|------|
| 端点认证 | 每个部署自动生成随机 API Key |
| 配置存储 | API Key 和搜索 Key 加密存储 |
| 网络隔离 | 平台部署的容器仅监听 0.0.0.0，但 Docker 网络隔离，仅内网可达 |
