## 2. 请求量规划

### 2.1 详细估算模型

```
日均请求量 = 活跃应用数 × 平均单应用日请求量
          = 30 个 × 33 万次
          ≈ 1,000 万次/天

峰值 QPS = 日均请求量 / 86400 × 峰值系数
         = 10,000,000 / 86,400 × 4
         ≈ 463 QPS → 向上取整 5,000 QPS

平均 QPS = 日均请求量 / 86400
         = 10,000,000 / 86,400
         ≈ 1,157 QPS → 约 1,200 QPS
```

### 2.2 各场景 QPS 分布

| 场景 | 请求占比 | 日均请求量 | 平均 QPS | 峰值 QPS |
|------|----------|-----------|----------|----------|
| 聊天补全（Chat） | 60% | 600 万 | 720 | 3,000 |
| 向量嵌入（Embedding） | 20% | 200 万 | 240 | 1,000 |
| 代码生成 | 10% | 100 万 | 120 | 500 |
| 图片生成 | 5% | 50 万 | 60 | 250 |
| 其他 | 5% | 50 万 | 60 | 250 |
| **合计** | **100%** | **1,000 万** | **1,200** | **5,000** |

### 2.3 增长预测

| 时间 | 预计日均请求量 | 预计峰值 QPS | 备注 |
|------|---------------|-------------|------|
| 上线初期（1-3 月） | 200 万 | 1,000 | 逐步接入应用 |
| 稳定期（4-6 月） | 500 万 | 2,500 | 主要应用接入完成 |
| 成长期（7-12 月） | 1,000 万 | 5,000 | 更多应用接入 |
| 第二年 | 1,500-2,000 万 | 7,500-10,000 | 业务增长 |

## 6. 风险缓冲建议

| 风险项 | 缓冲策略 | 具体措施 |
|--------|----------|----------|
| 请求量超预期 | 预留 50% 容量 | 网关和 API 服务支持水平扩展 |
| 存储增长超预期 | 预留 30% 空间 | 提前规划归档策略，使用对象存储 |
| 突发流量 | 限流 + 弹性扩展 | 配置限流阈值，K8s 自动扩缩容 |
| 硬件故障 | 冗余部署 | 关键组件多实例 + 主从架构 |
| 模型 API 延迟波动 | 超时 + 重试 | 配置合理超时时间，重试策略 |
